# چک‌لیست نهایی

## انجام‌شده در محیط تحویل
- بررسی بصری دسکتاپ و موبایل؛ فارسی RTL و انگلیسی LTR، روشن و تیره.
- رندر با فونت محلی و بدون منبع خارجی.
- بررسی syntax فایل‌های JS.
- تست خودکار Chromium: عرض‌های 360، 390، 768، 1024، 1440، 2560؛ هر دو زبان.
- بررسی نبود overflow افقی، تعداد بخش‌ها، گالری کیبوردی، Escape و برگشت فوکوس، منوی موبایل.
- تست فرم بدون اتصال؛ موفقیت و HTTP 500 با endpoint شبیه‌سازی‌شده (نه ارسال ایمیل واقعی).
- تست تاریخ نامعتبر و گذشته، افزودن بخش از داده، خراب شدن تصویر، no-JS و reduced-motion.
- گزارش نتیجهٔ واقعی در QA-results.json؛ شبیه‌سازی provider به معنی اتصال provider نیست.

## پیش از انتشار باید انجام شود
- [ ] جایگزینی تمام داده‌های نمونه و تصاویر مفهوم با اطلاعات واقعی.
- [ ] بررسی حقوق انتشار تصاویر و فونت‌ها؛ نگه‌داشتن مجوزها.
- [ ] تنظیم تاریخ واقعی آینده یا حذف تاریخ نمونه.
- [ ] اتصال سرور فرم، کنترل spam، نرخ درخواست، consent، double opt-in و سیاست حریم خصوصی.
- [ ] ارسال ایمیل واقعی و تست unsubscribe، bounce، خطای شبکه و timeout.
- [ ] تست با Safari، Firefox، iOS و Android واقعی؛ touch، landscape و zoom 200/400٪.
- [ ] تست دستی فقط با Tab/Shift+Tab/Enter/Escape، VoiceOver/NVDA، اعلان فرم و dialog.
- [ ] بررسی کنتراست با ابزار، اندازهٔ هدف لمس و audit کامل WCAG AA؛ این تحویل گواهی انطباق نیست.
- [ ] اجرای Lighthouse روی نسخهٔ production و موبایل حداقل سه بار؛ ثبت میانهٔ Performance/A11y/SEO/Best Practices، هدف بالای 90.
- [ ] ثبت FPS و long tasks با Performance panel، خصوصاً mask و SVG filter روی سخت‌افزار ضعیف.
- [ ] بررسی slow 3G، cache سرد، preload timeout و شکست دانلود font/image.
- [ ] تنظیم canonical، OG مطلق، JSON-LD واقعی، sitemap/robots و snapshot HTML دو‌زبانه.
- [ ] اطمینان از نبود console error، لینک شکسته، secret یا اطلاعات شخصی ناخواسته در build.

هیچ محصولی را صرفاً با یک تست Chromium «بدون باگ» اعلام نکنید.
