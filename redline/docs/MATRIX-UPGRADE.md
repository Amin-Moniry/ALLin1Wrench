رسم SVG و typewriter دارای paint محدود هستند؛ مانند canvas، ادعای compositor-only برای این دو نمی‌شود. فوتر قدیمی به‌شکل component مستقل و بدون Tailwind CDN، Font Awesome CDN یا iframe پس‌زمینهٔ قدیمی ادغام شده است.

گزارش‌های این مرحله در پوشهٔ [crimson](crimson/) قرار دارند. نتایج پوشهٔ `matrix/` به مرحلهٔ قبلی مربوط‌اند. شش فایل حفاظت‌شده همچنان بایت‌به‌بایت ثابت‌اند.


این ارتقا برای **پرتفوی ALLin1Wrench** است، نه پروژهٔ نقشه. هدف، افزودن یک لایهٔ نمایشی مستقل به REDLINE 03 بود؛ نه بازنویسی سایت یا جایگزینی پروژه‌ها.

## چرا این کتابخانه‌ها؟

**GSAP + ScrollTrigger** با جاوااسکریپت سادهٔ پروژه سازگار است: timeline و stagger بدون انتقال پروژه به React. استفاده از Framer Motion در این ساختار به تغییرات معماری غیرضروری نیاز داشت.

**Lenis** فقط روی اشاره‌گر دقیقِ دسکتاپ، با حرکت فعال، برای wheel smoothing اجرا می‌شود. روی موبایل و `prefers-reduced-motion`، اسکرول طبیعی باقی می‌ماند. anchorهای فعال و پنجره‌های dialog با مسیرهای موجود هماهنگ‌اند؛ Lenis هنگام dialog متوقف می‌شود.

هر سه فایل در مخزن میزبانی می‌شوند؛ بارگذاری سایت به CDN این کتابخانه‌ها وابسته نیست. مجوزهای کتابخانه‌ها از مجوز پرتفوی جدا هستند. هدرهای اصلی GSAP و ScrollTrigger و مجوز MIT مربوط به Lenis حفظ شدند.

## افزوده‌های نمایشیِ معرفی‌شده پیش از ساخت

۱. **ورودی سینمایی:** پنل «وارد جریان شو» داخل `#home` با حلقه‌ها، شمارنده‌های واقعیِ استخراج‌شده از DOM و مسیر ورود/ردکردن. پنل gate، لاگین یا لودر مسدودکننده نیست؛ محتوا از ابتدا قابل‌دسترسی است.

۲. **روایت اسکرول:** همان چهار مرحلهٔ قبلی در `#process` با فاصلهٔ روایی، کارت‌های عمودی و نشانگر sticky. متن و ترتیب مراحل از محتوا تغییر نکردند.

۳. **میدان تعاملی:** افزودهٔ صرفاً بصری در `#lab`؛ اشاره‌گر، کلیدهای جهت و بازنشانی. دو آزمایش قبلی در ادامه باقی‌اند. هیچ درخواست API یا اجرای مدل ایجاد نشده است.

بنابراین تعداد ۱۳ بخش اصلی و پنج پروژه همان است؛ افزوده‌ها داخل بخش‌های قبلی نصب می‌شوند.

### اختلاف ضروری بین دو خواستهٔ کارایی

«فقط transform/opacity» با «ترسیم canvas، رمزگشایی متن و انیمیشن واقعی blur/رنگ/gradient-stop» به‌طور کامل قابل‌جمع نیست.

- keyframeهای جابه‌جایی، پورتال، glitch، چرخش گرادیان و micro-interaction فقط transform/opacity را تغییر می‌دهند.
- blur، shadow و رنگ‌های شیشه ثابت‌اند؛ blur میان دو فریم انیمیت نمی‌شود.
- گرادیان روی یک حامل می‌چرخد؛ stopهای گرادیان در هر فریم دوباره تولید نمی‌شوند.
- canvas و رمزگشایی متن ذاتاً paint دارند؛ آن‌ها استثناهای بودجه‌بندی‌شده و محدودند، نه انیمیشن compositor خالص.
- کاهش حرکت، canvas ثابت، حذف چرخش/رمزگشایی/پورتال و Lenis غیرفعال را ایجاد می‌کند.

- **۶ بررسی سیاست کارایی:** توقف رسم بارش در dialog/سند مخفیِ شبیه‌سازی‌شده، fallback نبودن CSS timeline و رفتار موبایلِ touch/coarse.

### نرمی حرکت

هدف حرکت رابط نزدیک ۶۰fps است. نمونهٔ نهاییِ مستقل در Chromium headless / Linux، در عرض ۱۴۴۰ و ارتفاع ۱۰۰۰، فاصلهٔ فریم‌ها را ثبت می‌کند. عدد دقیق median و p95 در JSON بالا است. این نمونه، اندازه‌گیری روی گوشی یا تضمین fps تمام مرورگرها نیست؛ در اجرای هم‌زمان با تست‌های دیگر نیز فریم کندتر دیده شد.

بارش برای desktop pointer-fine تا cadence حدود ۶۰ و برای موبایل حدود ۳۰ بار رسم در ثانیه بودجه‌بندی شده است؛ این به معنی قفل‌کردن نرخ فریم کل رابط به ۳۰ نیست. بارش در tab مخفی یا dialog متوقف می‌شود. DPR و تعداد پیکسل محدودند و atlas گلیف‌ها دوباره استفاده می‌شود.

## اجرای تست‌ها


```bash
npm install --no-save playwright

CHROMIUM_PATH="$(node -p "require('playwright').chromium.executablePath()")" \
BASE_URL=http://localhost:8080 QA_DIR=qa-functional \
node redline/tests/matrix-root-regression.cjs

CHROMIUM_PATH="$(node -p "require('playwright').chromium.executablePath()")" \
```
